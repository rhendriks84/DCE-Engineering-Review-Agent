# DCE Review UI Prototype Requirements

## Design Principle
Upload first. Classification fields are optional hints and shall never block review.

## Intake Screen

### Required
- Upload package or artefact
- Free-text review request

### Optional
- Submission type: Auto-detect, MTS, Submittal, Drawing, Schematic, Single-Line Diagram, Calculation, Controls, Commissioning, CDE, D&E, Exception, Matrix, Other
- Discipline: Auto-detect or multi-select
- Region
- Project or programme
- Review scope
- Output format

## Reference Confirmation Screen
Show detected package type, disciplines, project, BOD, specifications, bulletins, prior baseline and status. Allow Accept, Override or Continue with limitations.

## Progress Screen
Show Intake, General Technical Review, Deviation Review and Output. Hide unused routes.

## Findings Screen
Filter by discipline, category, closure status, response party and decision owner.

## Decision Register
Show only DCE, Tech Gov, specialist, security-authority and AHJ decisions.

## Accessibility and Team Use
Use clear labels, keyboard-accessible controls, concise status text and permissions appropriate for DCE team-wide use.
