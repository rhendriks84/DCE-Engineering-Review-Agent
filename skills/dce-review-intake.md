# DCE Review Intake

## Purpose
Prepare and route a package without requiring the user to classify it first.

## Inputs
- Uploaded or referenced files
- Optional user hints: type, discipline, region, project, scope and output
- Available project context and prior baseline

## Responsibilities
- Inspect filename, cover, title block, content, revision, model and context.
- Accept formal packages and standalone drawings, schematics, single-line diagrams, calculations, sequences, schedules, datasheets and images.
- Treat UI selections as optional hints. Missing selections shall not block review.
- Classify as general technical, deviation or hybrid.
- Establish source precedence and reference-confirmation status.
- Propose, but never silently confirm, a provisional BOD.
- Ask one compact question only where ambiguity materially changes the basis, route or conclusion.
- Create the DCE Review Handoff Record and finding schema.

## Output
A populated handoff record with basis, assumptions, routes, deliverable, empty findings register, owners, evidence gaps and limitations.
